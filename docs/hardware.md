# Отчет по бенчмарку железа и инференсу модели

## 1. Характеристики машины
- **Процессор:** Intel Core i5
- **Оперативная память:** 16 ГБ RAM
- **Ускоритель / Device:** CPU
- **Операционная система:** Windows 11

## 2. Результаты замера (модель Qwen/Qwen3-0.6B)
- **Время загрузки модели:** 2.643 с
- **Медианная скорость инференса:** 6.21 токенов/сек
- **Пиковая RSS-память:** 1892.5 МБ

## 3. Обоснование выбора модели
Для текущей рабочей конфигурации на CPU выбрана модель `Qwen/Qwen3-0.6B`. Она умещается в оперативную память, не перегружает процессор и поддерживает отключение служебных блоков рассуждений (`enable_thinking: false`). Если на последующих этапах курса потребуется более быстрый отклик при локальной отладке, через `params.yaml` можно бесшовно переключиться на `HuggingFaceTB/SmolLM2-135M-Instruct` без изменения кода проекта.

## 4. Разбор исправленных дефектов проекта

### Дефект 1: Хардкод имени модели в коде
- **В чем заключался:** Название модели `Qwen/Qwen3-0.6B` было жестко вписано строками внутри файлов `src/model.py`, `src/generate.py` и `src/bench.py`.
- **Как проявлялся:** Изменение параметра модели в `params.yaml` не влияло на работу программы, а автотест `check.sh` падал на поиске строк с именами моделей через `grep`.
- **Как исправлен:** Удалены все строковые упоминания моделей из папки `src/`. Имя передается исключительно из `params.yaml` через функцию `load_params()["model"]["name"]`.

### Дефект 2: Зависимости без версий и отсутствие lock-файла
- **В чем заключался:** В файле `pyproject.toml` библиотеки были указаны без версий (`torch`, `transformers`), а файл блокировки `uv.lock` отсутствовал.
- **Как проявлялся:** Окружение было невоспроизводимым, что приводило к риску поломки проекта на других устройствах и в CI-пайплайнах при обновлении внешних библиотек.
- **Как исправлен:** В `pyproject.toml` зафиксированы минимальные поддерживаемые версии, добавлен параметр `[tool.uv] package = false`, и с помощью команды `uv sync` сгенерирован файл `uv.lock`.

### Дефект 3: Некорректный замер в bench.py (смешивание загрузки и генерации)
- **В чем заключался:** Замер времени включал в себя чтение весов модели с диска и их инициализацию, а прогревочный прогон перед замером отсутствовал.
- **Как проявлялся:** Рассчитанная скорость токенов в секунду получалась искусственно заниженной в несколько раз.
- **Как исправлен:** Замер разделен на независимые этапы: замер чистой загрузки модели (`load_time`), обязательный прогрев (`warmup_runs`), подсчет медианной скорости генерации за несколько итераций и мониторинг пикового потребления RSS-памяти процессом через `psutil`.

### Дефект 4: Невоспроизводимость генерации текста
- **В чем заключался:** В коде не фиксировался генератор случайных чисел (`seed`), а генератор всегда выполнял сэмплирование (`do_sample=True`).
- **Как проявлялся:** Повторные запуски с одинаковым промптом давали разный текст даже при значении `temperature: 0.0`.
- **Как исправлен:** Зафиксирован сид через `torch.manual_seed` и привязано условие `do_sample = temperature > 0`. При нулевой температуре генерация стала строго детерминированной.
